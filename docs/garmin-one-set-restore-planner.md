# One-set restore planner — 2026-10-13

Implemented pure `GarminOneSetRestorePlanner.Prepare(originalSnapshot, observedLiveSets, activityId)`. It prepares a **restoration request payload in memory** only after classifying current Garmin set data as `ChangedOneWeight` — the exact previously modeled Chest Press trial state (index 2, raw Garmin 22000 to 21000) with no other changes. It rejects `Original` and `Unexpected` states, verifies activity identity, starts from the untouched original snapshot rather than modifying server-returned data, and adds only the required per-set and nested-exercise `activityId` values through the established normalizer. The separate original snapshot remains intact. Three unit tests cover expected restore content, no-op and unexpected state rejection, and wrong activity ID.

**Not a live restore:** No CLI command invokes the Garmin PUT transport or this planner, and no Garmin record has been changed. A restore candidate does not prove the unofficial Garmin API will preserve server metadata or accept a round trip. Next engineering phase is a single-use orchestrated live trial with the existing verified backup, fresh baseline, explicit live-test action, immediate server readback, and independently invoked restoration when appropriate. If the server responds with an unexpected state, stop rather than blindly rewriting its data.
